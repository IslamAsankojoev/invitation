# Конструктор пригласительных сайтов (MVP)

Организатор настраивает приглашение в редакторе → изменения автосохраняются → он получает ссылку →
гость открывает страницу, слушает музыку и отправляет ответ (RSVP) → организатор видит список ответов.

Стек: Next.js 15 (App Router) · TypeScript strict · Tailwind CSS 4 · shadcn/ui (Radix) · Prisma + SQLite · Zod · dnd-kit ·
Vitest + React Testing Library · Playwright.

## Запуск

```bash
npm install          # заодно генерирует Prisma Client
npm run db:seed      # создаёт БД и демо-приглашение, печатает ссылки
npm run dev          # http://localhost:3000
```

`npm run dev` сам синхронизирует схему БД (`prisma db push`), так что `db:seed` для старта не обязателен.

| Команда | Что делает |
| --- | --- |
| `npm run dev` | Dev-сервер на :3000 (БД `prisma/dev.db`) |
| `npm test` | Unit-, компонентные и API-тесты (Vitest, отдельная БД `prisma/test.db`) |
| `npm run test:e2e` | Playwright, мобильный viewport (Pixel 7). Сам поднимает dev-сервер на :3100 с БД `prisma/e2e.db` |
| `npm run db:seed` | Пересоздаёт по демо-приглашению на каждый шаблон (`/i/demo`, `/i/demo-rose-garden`, `/i/demo-golden-autumn`, `/i/demo-starry-night`, `/i/demo-eucalyptus`, `/i/demo-art-deco`, `/i/demo-lavender-provence`, `/i/demo-marble-olive`) и печатает ссылки на редактор, публичную страницу и ответы |
| `npm run typecheck` | `tsc --noEmit` |

Перед первым `npm run test:e2e` установите браузер: `npx playwright install chromium`.

## Страницы и API

| Адрес | Назначение |
| --- | --- |
| `/` | Галерея шаблонов с живыми превью; «Выбрать» создаёт приглашение по шаблону |
| `/edit/[id]?token=…` | Редактор (без верного token — 403) |
| `/edit/[id]/guests?token=…` | Ответы гостей, счётчики, экспорт в CSV |
| `/i/[slug]` | Публичная страница приглашения |
| `POST /api/invitations` | Создать приглашение; тело `{ "template": "<id>" }` необязательно (по умолчанию «Кремовая классика», неизвестный id → 400) |
| `GET /api/invitations/[id]` | Публичные данные (без editToken) |
| `PATCH /api/invitations/[id]?token=…` | `{ data?, slug? }` → 200 / 400 (ошибки Zod) / 403 / 409 (slug занят) |
| `POST /api/upload` | `multipart/form-data`, поле `file`: `image/*` ≤ 5 МБ или `audio/mpeg` ≤ 10 МБ |
| `POST /api/invitations/[slug]/rsvp` | Ответ гостя: валидация, honeypot `website`, ≤ 5 ответов с IP в минуту |
| `GET /api/invitations/[id]/rsvp?token=…` | Список ответов и статистика |

## Интерфейс: shadcn/ui + Tailwind

Интерфейс приложения — главная, редактор, страница гостей, 403 — собран на [shadcn/ui](https://ui.shadcn.com)
(база Radix, стиль «Vega», иконки lucide). Компоненты лежат в `src/components/ui` и принадлежат проекту:
их можно править (например, `Slider` получил проп `thumbLabel` — доступное имя ползунка).
Добавить компонент: `npx shadcn@latest add <имя>`.

- Тема shadcn — CSS-переменные в `src/app/globals.css` (`--primary`, `--muted`, …); у редактора тёплый акцент.
- Выпадающие списки — `NativeSelect` (нативный `<select>`: удобнее на телефоне и стабилен в тестах).
- **Само приглашение** (то, что видят гости) shadcn не использует: у него собственный дизайн и классы `inv-*`
  (`.inv-btn`, `.inv-input`, …) на переменных палитры `--bg`, `--text`, `--accent`, `--font-*`.
  `--accent` задаётся на корне приглашения; снаружи него это токен shadcn.

Тема задаётся только CSS-переменными `--bg`, `--text`, `--accent`, `--font-title`, `--font-body`, `--title-scale`
(`lib/theme.ts`), шаблон приглашения один. Заголовки разделов всегда набраны Tenor Sans разрядкой (`--font-heading`).

**Шрифты** (все с кириллицей, подключены через `next/font` в `src/app/fonts.ts`):
- имена (`theme.font`, 17 шт.): Great Vibes, Marck Script, Bad Script, Caveat, Lobster, Pacifico, Amatic SC,
  Cormorant, Cormorant SC, Playfair Display, Prata, Forum, Yeseva One, Oranienbaum, Poiret One, Comfortaa, Inter;
- основной текст (`theme.bodyFont`, 10 шт. + «Авто»): Cormorant, Lora, EB Garamond, Playfair Display, Old Standard,
  PT Serif, Montserrat, Raleway, Manrope, Inter. «Авто» берёт пару к шрифту имён (`titleFonts[font].pair`).

Браузер скачивает файл шрифта только когда шрифт применён; заранее грузятся лишь шрифты стартового шаблона.

**Текстуры страницы** (`theme.texture`, 11 шт.): точки, крапинки, зерно бумаги, лён, клетка, штрих, сердечки, ромбы,
узор, звёздочки, акварель — чистый CSS/встроенный SVG, бесшовные и без загрузки файлов. На ночной палитре узоры
инвертируются и осветляют фон; акварель окрашивается цветом акцента палитры.

## Шаблоны

Четыре готовых оформления (`src/lib/templates.ts`), собранные из инструментов конструктора — палитры, шрифтов,
текстуры, падающего декора, конверта, фонов и украшений блоков, цветов дресс-кода:

| id | Название | Палитра / шрифт имён | Характер |
| --- | --- | --- | --- |
| `cream-classic` | Кремовая классика | кремовая / Great Vibes | сухоцветы, бумага, бант из бечёвки, лепестки роз |
| `rose-garden` | Розовый сад | пудровая / Marck Script | акварельный фон, розы с сиренью, розовые лепестки |
| `golden-autumn` | Золотая осень | осенняя / Playfair Display | зерно бумаги, клён и настурция, листопад |
| `starry-night` | Звёздная ночь | ночная / Poiret One | звёзды, золотые искры, белые розы, стеклянные карточки |

- Новое приглашение создаётся из шаблона (`createFromTemplate`) с примером текстов; `createDefaultInvitation()` —
  это первый шаблон.
- В редакторе («Оформление» → «Шаблон») шаблон можно сменить в любой момент: `applyTemplate` — чистая функция —
  заменяет тему (кроме фонового фото), фон и украшения блоков и цвета дресс-кода, но **сохраняет** имена, дату, тексты,
  программу, фото, музыку, порядок, видимость и заголовки блоков. Перед применением редактор спрашивает подтверждение.
- Превью в галерее и в редакторе — настоящий главный экран шаблона (`TemplatePreview`), уменьшенный через CSS.

**Как добавить шаблон:** допишите объект в массив `templates` — `id`, `name`, `description`, полную `theme`,
оформление блоков (`blocks: { calendar: { surface: "paper", ornaments: [orn("gardenia", "top-left")] }, … }` —
не указанные блоки получат «без фона, без украшений») и `dresscodeColors`. Тест `tests/unit/templates.test.ts`
проверит, что шаблон проходит схему и ссылается только на существующие картинки из `public/library`.

## Оформление: украшения, фоны блоков, декор

- **Украшения блока** (`block.ornaments`, до 6 на блок): картинка из библиотеки или своя, прижатая к углу или краю
  блока (8 положений), с размером, поворотом, отражением и прозрачностью. Украшение слегка выходит за край и
  обрезается блоком — как живой букет по углу открытки. Есть у каждого блока, включая главный экран.
- **Фон блока** (`block.surface`): без фона, «Бумага» (рваный лист), «Рваный край» (белая полоса), «Карточка».
  Прозрачность фона (`block.surfaceOpacity`, 10–100 %) меняется ползунком; фон рисуется отдельным слоем,
  поэтому текст и украшения остаются чёткими. На плотной бумаге (≥ 50 %) текст тёмный в любой палитре,
  на более прозрачной — берёт цвет темы, чтобы оставаться читаемым сквозь фон.
- **Заголовок блока** (`block.title`): свой текст; пустая строка — без заголовка; «Сбросить» — стандартный.
- **Падающий декор** (`theme.decor`): фигуры (лепестки, сакура, конфетти, снег) или **картинка** — лепестки роз,
  осенний лист или любая своя PNG. Картинка «переворачивается» в полёте. Плотность 0–60, размер ×0.5–×3.
- **Конверт** (`theme.envelope.ornament`): картинка в углах первого экрана; монограмма на печати строится из имён.
- **Текстура страницы** (`theme.texture`): точки или крапинки поверх фона (чистый CSS, без стыков).
- Главный экран может быть на **фото** пары (`hero.photo`), место — с фото зала (`location.photo`),
  у пунктов программы есть описание.

Старые приглашения продолжают открываться: у новых полей в схеме есть значения по умолчанию.

## Как добавить картинку в библиотеку

1. Положите прозрачный PNG/WebP в `public/library/` (лучше заранее уменьшить до ~900 px и сжать в WebP).
2. Допишите строку в `library` в `src/lib/library.ts`:
   ```ts
   asset("lavender", "Лаванда", "flowers"), // id = имя файла без .webp; категория: flowers | leaves | accents | particles
   ```
3. Всё: картинка появится в окне выбора украшений (и декора, если категория `particles`).

## Как добавить шрифт или текстуру

**Шрифт.** Проверьте, что у шрифта есть кириллица (`subsets` в Google Fonts), затем:
1. `src/app/fonts.ts` — объявите его (`Neucha({ subsets: ["latin", "cyrillic"], preload: false, weight: "400",
   variable: "--font-neucha" })`) и добавьте в массив `fontVariables`. Аргументы — только литералы.
2. `src/lib/schema.ts` — ключ в `FONTS` (для имён) и/или `BODY_FONTS` (для текста).
3. `src/lib/theme.ts` — запись в `titleFonts` (`label`, `css`, `pair` и при необходимости `scale`, если глифы
   крупные/мелкие) и/или `bodyFonts`. Кнопка с образцом появится в редакторе сама.

**Текстура.** Ключ в `TEXTURES` (`schema.ts`) и запись в `textures` (`library.ts`): `label`, `css` (значение CSS
`background`; для узоров удобен помощник `svgTile(размер, "<svg-элементы>")`, рисуйте чёрным) и `opacity`.
Цветным текстурам на `var(--accent)` ставьте `tinted: true`.

## Как добавить новый тип блока

Пример — блок `gallery` с полем `photos`.

1. **Схема** — `src/lib/schema.ts`: опишите блок (общие поля — через `...blockBase`) и добавьте его в `discriminatedUnion`:
   ```ts
   export const galleryBlockSchema = z.object({ type: z.literal("gallery"), ...blockBase, photos: z.array(imageUrl).max(12) });
   export const blockSchema = z.discriminatedUnion("type", [/* …, */ galleryBlockSchema]);
   ```
   После этого TypeScript сам подсветит все места, где блок нужно зарегистрировать (шаги 2–4).
2. **Названия** — `blockLabels` (в редакторе) и `defaultTitles` (заголовок на странице) в `src/lib/blocks.ts`.
3. **Компонент для гостей** — `src/components/invitation/blocks/GalleryBlock.tsx`
   (`({ block, ctx }: BlockProps<"gallery">) => <Section block={block}>…</Section>` — `Section` сам нарисует
   фон, украшения и заголовок), затем зарегистрируйте его в `blockComponents` (`blocks/registry.ts`).
4. **Поля редактора** — функция `GalleryFields` в `src/components/editor/BlockFields.tsx` и запись в `blockFields`.
   Фон, заголовок и украшения редактор добавит сам.
5. **Значение по умолчанию** — добавьте блок в массив `blocks` в `createDefaultInvitation()` (`src/lib/defaults.ts`),
   иначе в новых приглашениях его не будет. У старых приглашений блока нет, пока его не добавят в данные.
6. **Тесты** — проверьте, что дефолтное приглашение валидно, и добавьте тип в ожидаемый порядок в
   `tests/components/InvitationView.test.tsx`. Запустите `npm test`.

## Как добавить новый вид декора

Если нужна просто другая картинка (например, лепесток лилии) — достаточно добавить её в библиотеку с категорией
`particles` и выбрать декор «Картинка». Новый *вид* анимации:

1. `src/lib/schema.ts` — добавьте значение в `DECOR_TYPES` (например, `"hearts"`).
2. `src/lib/decor.ts` — подпись в `decorLabels` и объект в `decorDrawers`:
   `fall` (скорость падения), `sway` (покачивание), `sizeRange` и `draw(ctx, p, image?)` — рисует одну частицу
   в точке (0, 0); поворот, прозрачность и цвет из `theme.decor.color` уже выставлены.
3. Всё. Пункт появится в выпадающем списке «Декор», а `DecorLayer` начнёт его рисовать
   (при `prefers-reduced-motion` частицы неподвижны).

## Что заменить для продакшена

- **Авторизация.** Сейчас доступ к редактору даёт `editToken` в URL (сравнение строк). Нужны аккаунты
  (например, NextAuth/Clerk), привязка приглашений к владельцу, проверка прав в `PATCH`, `GET rsvp`, на страницах
  редактора и гостей. Загрузку файлов (`/api/upload`) тоже закрыть авторизацией.
- **Хранилище файлов.** Реализуйте интерфейс `Storage` из `src/lib/storage.ts` для S3 / Supabase Storage и
  замените экспорт `storage`. Больше ничего менять не нужно: в данных хранится только публичный URL.
  Локальное хранилище подходит только для разработки: `next start` не отдаёт файлы, добавленные в `public/` после сборки.
- **База данных.** В `prisma/schema.prisma` поменяйте `provider` на `postgresql`, задайте `DATABASE_URL`
  и перейдите с `db push` на миграции (`prisma migrate`). Поле `data` можно сделать `Json` (сейчас это строка с JSON,
  которая всегда проходит через Zod при чтении и записи).
- **Лимит частоты RSVP** — сейчас в памяти процесса; в нескольких инстансах нужен Redis/Upstash.
- Удаление неиспользуемых файлов из хранилища, CAPTCHA вместо/вместе с honeypot, мониторинг ошибок.

## Допущения

- **Сегмент `[key]` в API.** Next.js не разрешает разные имена динамических сегментов на одном уровне
  (`[id]` и `[slug]`), поэтому папка называется `api/invitations/[key]`: для `GET`/`PATCH` и `GET …/rsvp` это id,
  для `POST …/rsvp` — slug (как в задании).
- **Дата события** хранится как локальное время без часового пояса: `"YYYY-MM-DDTHH:mm"`
  (формат `<input type="datetime-local">`). В `.ics` она пишется как «плавающее» время (`DTSTART:20270619T160000`),
  календарь покажет его в поясе пользователя. Обратный отсчёт тоже считается в поясе гостя.
  Длительность события в `.ics` — 4 часа.
- **«Всего гостей»** — сумма `guestsCount` только у тех, кто придёт. Если гость ответил «Не смогу», поле числа гостей
  скрыто и отправляется `1`.
- **Honeypot** заполнен → `400`, ответ не сохраняется. Лимит — 5 ответов с IP в минуту (`429`).
- **Дедлайн RSVP** только показывается гостю, ответы после него не блокируются.
- **Кнопка «Добавить в календарь»** находится в блоке «Главный экран» (дата и имена берутся оттуда, место —
  из блока «Место»). Если главный экран скрыт, кнопки нет.
- **Countdown и «Календарь»** без блока hero не рендерятся — оба берут дату оттуда.
- **Стандартные заголовки** свадебные («Дата свадьбы», «Программа дня»…); для дня рождения их меняют в поле
  «Заголовок» у блока.
- **Библиотека картинок** хранится в репозитории (`public/library`, ~1 МБ WebP) и отдаётся как статика; свои картинки
  загружаются через тот же `/api/upload` (только `image/*` до 5 МБ).
- **Фон** (`theme.background`) — URL загруженного изображения; поверх накладывается полупрозрачный градиент
  цвета `--bg`, чтобы текст оставался читаемым.
- **Приглашение всегда создаётся из шаблона** и сразу выглядит готовым — организатор меняет тексты и фото.
  Смена шаблона не трогает содержимое, но сбрасывает ручные настройки оформления (об этом предупреждает диалог).
- **Slug** меняется кнопкой «Сохранить» во вкладке «Ссылка», а не автосохранением: смена ссылки ломает уже
  разосланные адреса, поэтому это отдельное явное действие.
- **Невалидные данные в редакторе** (например, пустые имена) не сохраняются: индикатор показывает
  «Есть ошибки — не сохранено» и список ошибок Zod.
- **Удаление музыки** обнуляет `music.url`, сам файл остаётся в хранилище.
- **Ответ 403 в редакторе** отдаётся через `forbidden()` — для этого в `next.config.ts` включён
  `experimental.authInterrupts`.
- **После «Создать приглашение»** выполняется обычный переход на страницу редактора (`location.assign`),
  а не клиентская навигация: так надёжнее при первой компиляции маршрута в dev-режиме.
- **Тестовые БД** не пересоздаются командой `--force-reset` (Prisma запрещает её запуск из AI-агентов без явного
  согласия пользователя): `db push` только синхронизирует схему, API-тесты сами чистят таблицы.
  E2E каждый раз создаёт новое приглашение, так что старые данные в `e2e.db` ему не мешают.
- **E2E идёт против `next dev`**, а не `next start`, потому что загруженный mp3 должен сразу раздаваться из
  `public/uploads` (см. «Хранилище файлов» выше). Сборка для E2E лежит в `.next-e2e`, чтобы не мешать `npm run dev`.
- **Drag-and-drop в E2E** выполняется с клавиатуры (пробел → ↑ → пробел): это штатный доступный режим dnd-kit,
  и он стабильнее эмуляции жеста мышью. Объявления для скринридеров переведены на русский.
