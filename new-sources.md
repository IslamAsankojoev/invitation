## 1. Что уже сделано до этого чата (кратко)

- **Украшения.** Библиотека `src/lib/library.ts` (`library`, категории `flowers | botanical | leaves | wreaths |
  frames | dividers | watercolor | accents | particles`). Недавно добавлена категория «Ботаника» — 18 старинных
  гравюр (Редуте и др.), вырезанных из сканов скриптом `scripts/botanical-cutout.mjs`.
- **Фоны блока = предметы, а не фактуры** (важное решение пользователя, см. память `block-backgrounds-are-objects`):
  фон — это вещь, на которой лежит текст (лист, тетрадь, рама, тарелка, открытка…), а не «обои» на весь блок.
  Мрамор/штукатурка/эбру и т.п. пользователь отверг. Сейчас фоны: `plain, paper, card, vellum, crumpled,
  notebook, frame, plate` (`SURFACES` в `src/lib/schema.ts`). Убранные значения читаются через `LEGACY_SURFACES`.
- **Как рисуется фон-предмет** (`surfaceLayer()` в `library.ts`, общая для приглашения и плиток редактора):
  - `surfaceObjects[id] = { kind: "border", src, slice, width, repeat, fill?, window?, crest? }` — картинка
    режется как CSS `border-image`: углы и края не искажаются, середина тянется (`stretch`) или повторяется
    (`round`) — годится для блоков любой высоты. `slice` — в пикселях файла, `width` — толщина краёв на странице.
    `window` — заливка «окна» рамы (паспарту, обычно `var(--tex-base)`), `crest` — украшение над рамой отдельным
    `<img>` (не растягивается). Пример — `frame` (золочёная рама с лавровым венцом).
  - `{ kind: "contain", src }` — предмет целиком по центру (круглая тарелка). Только для коротких блоков
    (таймер, дресс-код, место); содержимое уменьшается `zoom: .78` (`.surface-plate` в `globals.css`).
  - Отступы содержимого под края предмета — класс `.surface-<id>` в `src/app/globals.css`.
  - Светлые предметы (текст принудительно тёмный) — `lightSurfaces`.
  - Плитка в редакторе показывает `surfaceThumb(id)` (= `src` предмета).
- **Рецепт «Фон-предмет»** и «Картинка в библиотеку» — в `AGENTS.md` §9.

## 2. Лицензии — ВАЖНО

pngwing.com сам ничего не лицензирует: у картинок пометка «Non-commercial use», многие — чужие вырезки.
Пользователь сказал, что **приобретёт** нужные картинки (у оригинальных авторов). Поэтому:

- В `public/library/CREDITS.md` для каждой картинки из `new-sources/` добавь строку с исходным именем файла,
  источником `pngwing.com` и статусом лицензии **«уточняется (купить у автора)»** — не пиши CC0/PD.
- Тест `tests/unit/library.test.ts` сейчас требует `CC0|Public domain` у `botanical` и у фонов. Расширь его:
  допускай `Лицензия приобретена` и `уточняется`, но **каждая** картинка должна иметь строку в CREDITS.md.
- Не публикуй и не выкладывай эти файлы наружу; перед продакшеном — пройтись по статусам «уточняется».

## 4. Как делать

1. **Сначала покажи план пользователю**: контактный лист (sharp → jpg на сером фоне) с номерами и что из чего
   получится; спорные — спросить. Пользователь просил предметы «со вкусом», тематические для приглашения.
2. **Разрезание составных** (13, 14, 39, 40, 51): по альфа-каналу — связные области (как в
   `scripts/botanical-cutout.mjs`: маска → «расширение» на пару px → flood fill → bbox каждой области с
   отступом). Лучше оформить скриптом `scripts/split-sheet.mjs <in.png> <outDir>` — пригодится ещё.
3. **Чистка:** обрезать по альфе (`trim`), уменьшить до ≤ 1200 px по длинной стороне (украшения ≈ 900 px),
   сохранить `webp` (quality 80–85, alphaQuality 90). Выровнять повёрнутые листы (29, 30). Текст на предметах
   (36, 49, sakura) — закрасить цветом бумаги соседних пикселей или отказаться от картинки.
4. **Имена:** украшения — `public/library/<id>.webp` (id на английском, кебаб-кейс: `sticker-pink`,
   `ribbon-gold-1`, `wc-blue-stroke`), фоны — `public/library/surfaces/<id>.webp`.
5. **Регистрация:**
   - украшение → `asset(id, "Подпись", category)` в `library` (`library.ts`);
   - фон → ключ в `SURFACES` (schema.ts), `surfaceLabels`, `surfaceObjects` (+ класс `.surface-<id>` в
     globals.css, при необходимости в `lightSurfaces`), при желании в `premiumSurfaces` (premium.ts).
   - Фонов станет ~25 — плитки в `SurfacePicker` (BlockStyle.tsx) сетка 4 колонки; возможно, понадобится
     группировка (Бумага / Карточки и билеты / Рамы / Тарелки и салфетки) — предложи пользователю.
6. **Проверка на живом приглашении** (обязательно, скриншоты пользователю):
   - dev-сервер `preview_start dev-auto` (порт 3300; конфиг в `.claude/launch.json`);
   - тестовое приглашение: `POST /api/invitations {template}` → `PATCH /api/invitations/:id?token=` с нужными
     `surface` у блоков → `/i/<slug>`; открыть конверт кнопкой «Открыть приглашение»;
   - проверить на светлой и тёмной палитре (`starry-night`, `art-deco`), на коротком (таймер) и длинном (анкета)
     блоке;
   - скриншоты в панели браузера запаздывают — после прокрутки менять размер окна (`resize_window` 430↔431),
     анимации дожимать `document.getAnimations().forEach(a => a.finish())` и ставить `data-revealed`.
7. **Перед сдачей:** `npx tsc --noEmit`, `npm test`, `npm run test:e2e`; обновить `AGENTS.md` (§5.7, §9, §11) и
   `CREDITS.md`. Проект не под git — перед большой переделкой архив (`tar czf before-new-sources.tgz …`, см.
   AGENTS.md §7 п.14). Не запускать `prettier --write` (нет конфига, переформатирует под 80 символов).

## 5. Что НЕ делать

- Не рисовать фоны/украшения самому (SVG/CSS) — пользователь просит использовать найденные картинки.
- Не делать фоны-«обои» (сплошная фактура на весь блок).
- Не писать CC0/PD для картинок с pngwing.
- Не удалять `new-sources/` — это исходники; результат складывать в `public/library/`.
