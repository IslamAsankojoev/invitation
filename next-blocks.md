## Этап 1 — СДЕЛАН (сентябрь 2026)
Реализовано по плану ниже; одиночными оставлены `hero` и `rsvp` (рекомендация, у пользователя не переспрашивали —
поменять можно в `SINGLE_BLOCK_TYPES`). Главный экран нельзя удалить (только скрыть). Детали — AGENTS.md §4, §5.2, §5.3.
Не сделано из плана: «+» между блоками (есть только кнопка внизу списка); шаблоны пока не задают оформление новым
типам (`text/photo/gallery/contacts` получают «без оформления»); в новые приглашения новые типы не входят.

## Этап 1 (исходный план): неограниченное число блоков любого типа

Решение пользователя: блоков может быть сколько угодно, **перед добавлением выбирается тип блока**.

### Модель данных
- У блока появляется `id` (строка, `nanoid`/`crypto.randomUUID`). **Обратная совместимость:** старые JSON без `id`
  → `z.preprocess` выдаёт стабильный id (например, `b-${type}` для первого блока типа — чтобы seed-ы и ключи не
  прыгали). Добавь тест в `schema.test.ts` («старые приглашения без id читаются»).
- Убрать `superRefine` «блок встречается больше одного раза» в `schema.ts` (и тест «отклоняет дубликат типа»
  переделать в «id уникальны»). Лимит на число блоков (например, 40) — защита от раздувания JSON.
- **Уточнить у пользователя одиночные типы:** рекомендую `hero` и `rsvp` оставить по одному (дата/имена
  берутся из hero; ответы гостей одни на приглашение). Остальные — без ограничений.

### Всё, что сейчас завязано на уникальность `block.type` (переделать на `id`)
- `lib/blocks.ts`: `toggleBlock/updateBlock/addOrnament/updateOrnament/removeOrnament(data, type, …)` → по `id`;
  `findBlock(data, "hero")` оставить (первый блок типа) — им берут дату/имена/место:
  `app/i/[slug]/page.tsx`, `edit/[id]/guests/page.tsx`, `InvitationPage`, `IntroPreview`, `ThemePanel`,
  `CountdownBlock`, `CalendarBlock`, `StoryBlock`, `LocationBlock`, `HeroBlock` (placeOf — первое место).
- `InvitationView.tsx`: `key={block.type}` → `key={block.id}`.
- `Section.tsx`: `data-block={block.type}` оставить (стили/тесты), добавить `data-block-id`.
- `BlocksPanel.tsx`: dnd-kit id и `key` — по `id`; объявления для скринридеров («Блок «Программа» над блоком «…»»)
  — с номером, если типов несколько («Текст 2»). E2E `tests/e2e/full-flow.spec.ts` ждёт эти объявления.
- `Editor.tsx`: раскрытый блок и прокрутка превью (`[data-block="${type}"]`) → по `id` (`[data-block-id=…]`).
- `lib/edges.ts`: `defaultEdgeSeed(block.type, …)` → от `id` (у новых блоков зерно и так в данных).
- `lib/templates.ts`: `designFor(template, block.type)` оставить по типу (оформление типа); `sampleBlocks()` —
  с id; `applyTemplate` не должен терять лишние блоки.
- Заголовки по умолчанию (`defaultTitles`) — одинаковые у двух блоков одного типа, это ок.

### Редактор
- Кнопка «Добавить блок» (внизу списка и/или «+» между блоками) → `Dialog` со списком типов (плитка: иконка,
  название, одна строка описания; как `TemplatePicker`/`VariantPicker`). Новый блок — после раскрытого или в конец,
  сразу раскрыт, превью прокручено к нему. Содержимое по умолчанию — из `sampleBlocks()` для этого типа,
  оформление — текущего шаблона (`designFor`).
- В строке блока: «Дублировать» и «Удалить» (удаление — через `AlertDialog`, как смена шаблона).
- Одиночные типы в диалоге неактивны с подписью «уже есть».

### Новые типы блоков (рецепт «Новый тип блока» в AGENTS.md §9)
1. **`text`** — универсальный: иконка (опц., линейные иконки как в `PROGRAM_ICONS`), заголовок, текст, кнопка
   (подпись + ссылка, опц.). Из него: «Пожелания», «Подарки», «Только взрослые», «Детали», «Дорогие гости».
   Виды: classic / card / quote. Стоит дать пресеты при добавлении («Пожелания», «Подарки»…) — это тот же `text`.
2. **`photo`** — фото во всю ширину блока (без текста или с подписью), высота (авто/экран/квадрат), края
   (уже есть `edgeTop/edgeBottom`), ширина `full` по умолчанию.
3. **`gallery`** — 2–9 фото: сетка / коллаж / лента с прокруткой, лайтбокс по нажатию.
4. **`contacts`** — люди (имя, роль «организатор», телефон) + кнопки WhatsApp / Telegram / позвонить
   (`https://wa.me/…`, `https://t.me/…`, `tel:`).
Для каждого: схема (`...blockBase`, `variant`), `blockLabels/defaultTitles`, компонент в `invitation/blocks`
через `<Section>` (+ `textStyle(block, key)` на каждом тексте — AGENTS §5.7 «Цвет и шрифт текста»), `registry.ts`,
поля в `BlockFields.tsx` (с `TextStylePicker`), пример в `sampleBlocks()`, тесты.

## Этап 2 — СДЕЛАН: заливка секции цветом
`bgColor` у блока: заливка во весь блок (режется краями) или цвет панели; текст и акцент «переворачиваются» по
яркости (`inv-fill-dark/light`). Подробно — AGENTS.md §5.7.

## Шаблоны по примерам — СДЕЛАНО (4 из 8)
По примерам №4, №5, №6, №8 собраны шаблоны со своей структурой: «Посадочный талон», «Итальянское озеро», «Морской
берег», «Шоколад и сургуч» (AGENTS.md §5.1). Заодно сделаны из этапа 4: обложки «Монограмма» (без цитаты и родителей)
и «Посадочный талон», плюс «Фото сверху»; из этапа 5: жемчуг, ракушка, сургуч. Не сделаны примеры №1 (эвкалипт,
иконки в программе на акварельной полосе), №2 (история-лента с полароидами), №3 (эскизы, извилистая программа,
банты в дресс-коде), №7 (белые маки, атласные ленты, фото нарядов) — им нужны виды из этапа 4 и картинки из этапа 5.

## Этап 3: свои вопросы в анкете
`rsvp.questions[]`: да/нет, выбор из вариантов, число, текст. Ответы — в `Rsvp` (JSON-поле), страница гостей и CSV
показывают столбцы по вопросам. Нужна миграция схемы Prisma (`db push`; тестовые БД не сбрасывать — AGENTS §7 п.10).

## Этап 4: новые виды существующих блоков
- hero: монограмма «R | J» + цитата + родители; «посадочный талон»; крупная дата «FRIDAY | 14 | 2023».
- story: лента по годам с полароидами (`items[]` с годом, текстом, фото).
- program: извилистая линия от руки (SVG-путь).
- dresscode: фото-примеры нарядов, подписи цветов, образцы-картинки (банты).
- навигация-меню сверху (якоря на блоки) — опция приглашения.

## Этап 5: библиотека
Линейные иконки (кольца, бокалы, торт, диско-шар, стул, подарок, конверт), штриховые иллюстрации (дом, бокалы),
шёлковые ленты, жемчуг, ракушки, белые маки. Лицензии — AGENTS §9 «Картинка в библиотеку» и `CREDITS.md`.

## Долг по тестам (пользователь отложил — «тесты проведём потом»)
Для недавних фич новых тестов нет; существующие 190 тестов проходят:
- края блока (`lib/edges.ts`: маски, `blockEdges`, `defaultEdgeSeed`), генератор `lib/tornEdge.ts`
  (детерминированность, размеры, бесшовность), API `/api/edges/torn` (400/200/кэш),
  перегенерация обрыва в `EdgePicker` (выбор, повторный клик, «Другой обрыв»);
- фоновая картинка блока (`bgImage/bgDim/bgBlur/bgDarken`, светлый текст от 0.45), ширина `full` (`isFullWidth`);
- стиль текста (`textStyle`, `withTextStyle`, `TextStylePicker`);
- E2E-сценарий под это и `next build`.
